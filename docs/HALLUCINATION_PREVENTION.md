# Hallucination Prevention & Letter Quality Guardrails

## Overview

This document describes the multi-layered system implemented to prevent AI hallucinations and ensure letter quality in the Legal Document Analysis Portal. These guardrails are critical because letters generated by the system are sent to real clients.

## Problem Statement

AI language models can fabricate:
- Facts, dates, or amounts not in source documents
- Case citations that don't exist
- Contract clauses or quotes not in provided documents
- Statements attributed to parties without documentation
- Overly optimistic assessments of weak or non-viable cases

## Implementation Architecture

The hallucination prevention system operates at four levels:

```
┌─────────────────────────────────────────────────────────────────┐
│                    LETTER GENERATION FLOW                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. GAP ANALYSIS                                                │
│     ├── Missing documents detection                             │
│     ├── Factual contradictions                                  │
│     ├── Timeline gaps                                           │
│     ├── Unverifiable claims                                     │
│     └── Hallucination risk identification (NEW)                 │
│                                                                 │
│  2. COMPLETENESS GATE                                           │
│     ├── Score < 40% → BLOCKED (HTTP 409)                        │
│     └── Score 40-60% → WARNING logged                           │
│                                                                 │
│  3. PROMPT GUARDRAILS                                           │
│     ├── Step 0.5: Viability assessment                          │
│     ├── Step 0.75: Gap analysis guardrails                      │
│     └── Step 0.8: Source attribution requirements (NEW)         │
│                                                                 │
│  4. POST-GENERATION VALIDATION                                  │
│     ├── Amount verification against financial_data              │
│     ├── Date verification against timeline                      │
│     ├── Unverifiable claim hedging check                        │
│     └── Case citation verification                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Component Details

### 1. Gap Analysis Enhancement

**File:** `src/legal_portal/services/gap_analysis_service.py`

The gap analysis now identifies five categories of issues:

| Category | Description |
|----------|-------------|
| `missing_document` | Documents referenced but not provided |
| `factual_contradiction` | Conflicting information across documents |
| `timeline_gap` | Missing or out-of-sequence dates |
| `unverifiable_claim` | Claims without supporting evidence |
| `hallucination_risk` | Facts that could be fabricated |

**Hallucination Risk Detection** includes:
- Facts stated without document support
- Legal conclusions without statutory basis
- Implied information that should be explicit
- Calculations or derived dates/amounts
- Assumptions about opposing party positions
- Unquoted contract terms

### 2. Completeness Gate

**File:** `src/legal_portal/api/routes/analysis.py`

Before generating any letter, the system checks the gap analysis completeness score:

```python
if gap_analysis.overall_completeness_score < 40:
    raise HTTPException(
        status_code=status.HTTP_409_CONFLICT,
        detail={
            "error": "documentation_insufficient",
            "message": "Case documentation is insufficient for letter generation",
            "completeness_score": gap_analysis.overall_completeness_score,
            "critical_gaps": gap_analysis.critical_count,
            "recommendation": "Review the Gap Analysis tab..."
        }
    )
```

| Score | Behavior |
|-------|----------|
| < 40% | **BLOCKED** - Letter generation prevented (unless overridden) |
| 40-60% | **WARNING** - Logged, letter generated with caution |
| > 60% | Normal generation |

### 2.1 Force Generation Override (NEW)

In cases where an attorney decides to proceed despite insufficient documentation, the system allows an override:

**API Parameters:**
- `force_generation: bool = False` in `LetterGenerationRequest`
- `?force_generation=true` query parameter for streaming endpoint

**Behavior:**
- When `force_generation=true` is provided with completeness < 40%, the system:
  1. Logs a warning: `"OVERRIDE: force_generation used for case {case_id}"`
  2. Proceeds with letter generation
  3. Letter may contain gaps or require significant manual review

**Frontend UI:**
- Warning banner displays when letter generation is blocked
- Checkbox: "Force generation despite insufficient documentation"
- Additional warning text when checkbox is enabled

```python
if gap_analysis.overall_completeness_score < 40:
    if not letter_request.force_generation:
        raise HTTPException(status_code=409, ...)  # Blocked
    else:
        logger.warning(f"OVERRIDE: force_generation used for case {case_id}")
        # Proceed with generation
```

### 2.2 Case Recommendation System (NEW)

The gap analysis now generates a case recommendation based on viability, completeness, and gap severity:

| Condition | Recommendation | Color | Suggested Letter |
|-----------|----------------|-------|------------------|
| `!is_viable` OR `score < 30` OR `critical >= 3` | NOT_VIABLE | red | Declination |
| `score < 60` OR (`critical >= 1` AND `high >= 2`) | NEEDS_DOCUMENTATION | yellow | Document Request |
| `case_strength == "weak"` OR (`high >= 3` AND `score < 75`) | SETTLEMENT_RECOMMENDED | orange | Settlement Advisory |
| Otherwise | STRONG_CASE | green | Proceed (Engagement) |

**Implementation:** `src/legal_portal/services/gap_analysis_service.py` (`_generate_recommendation`)

**Data Model:** `src/legal_portal/core/data_models.py`
```python
class CaseRecommendation(BaseModel):
    category: CaseRecommendationCategory  # strong_case, needs_documentation, etc.
    confidence: ConfidenceLevel  # high, medium, low
    reasoning: str  # 2-3 sentences explaining the recommendation
    next_steps: List[str]  # Action items for attorney
    suggested_letter_type: RecommendedLetterType
    category_display_name: str  # UI-friendly label
    category_color: str  # green/yellow/orange/red
```

**Advisory Letter Types:**
- **Proceed (Engagement):** Confirms firm will take the case
- **Request Documents:** Lists specific missing documents needed
- **Settlement Advisory:** Recommends considering settlement
- **Declination:** Professionally declines representation

### 3. Source Attribution Requirements (Prompt)

**File:** `src/legal_portal/prompts/findings_letter_prompt.txt`

Step 0.8 in the prompt enforces source traceability:

**For Dates:**
- Only use dates from the TIMELINE section
- No calculating dates ("30 days later...")

**For Amounts:**
- Only use amounts from FINANCIAL DATA
- No estimated or calculated amounts

**For Quotes:**
- Only quote text visible in documents
- No assumed contract clauses

**For Legal Citations:**
- Only cite VERIFIED STATUTES
- No fabricated case law

**For Party Statements:**
- Only attribute documented statements
- Use hedging: "According to the intake form..."

**Absolute Prohibitions:**
1. NEVER invent case citations
2. NEVER fabricate contract terms
3. NEVER calculate dates
4. NEVER estimate amounts
5. NEVER create party statements

### 4. Post-Generation Validation

**File:** `src/legal_portal/services/letter_validation_service.py`

The `LetterValidationService` validates generated letters:

```python
class LetterValidationService:
    def validate_letter(
        self,
        letter_html: str,
        fact_matrix: FactMatrix,
        gap_analysis: Optional[GapAnalysisResult],
        verified_statutes: List[Dict],
    ) -> LetterValidationResult:
        # Validates amounts, dates, claims, citations
```

**Validation Checks:**

| Check | What It Does |
|-------|--------------|
| Amount Validation | Compares letter amounts to `financial_data` |
| Date Validation | Compares letter dates to `timeline` |
| Hedging Check | Ensures unverifiable claims use hedging language |
| Citation Check | Flags potential fabricated case citations |

**Warning Types:**
- `amount_mismatch` - Amount not in financial data
- `date_mismatch` - Date not in timeline
- `unhedged_claim` - Unverifiable claim without hedging
- `unverified_citation` - Case citation not in verified sources

### 5. Enhanced Viability Assessment

**File:** `src/legal_portal/services/multi_stage_analyzer.py`

The deep analysis now evaluates viability across three dimensions:

**Legal Viability:**
- Facts don't support any legal claim
- Statute of limitations expired
- Client's conduct bars recovery
- Insufficient evidence
- Unassailable defenses

**Practical Viability (NEW):**
- Defendant cannot be identified/located
- Recovery less than litigation costs
- Procedural requirements cannot be met
- Client lacks standing
- Res judicata/collateral estoppel bars claim
- Defendant appears judgment-proof

**Document Completeness:**
- Critical documents missing
- Client's documents contradict their claims
- Key evidence unavailable

## Expected Behavior

| Scenario | System Response |
|----------|-----------------|
| Completeness < 40% | Letter generation **blocked** with HTTP 409 |
| Completeness 40-60% | Warning logged, attorney notice in letter |
| `is_viable = false` | "NO VIABLE CASE" letter template used |
| Missing key document | Letter notes document unavailable |
| Unverifiable claim | Hedging language required |
| Amount not in data | Validation warning logged |
| Fabricated citation | Validation warning logged |

## Hedging Language Examples

When a fact cannot be verified from documents, the system requires hedging:

**Good (Hedged):**
- "Based on the information provided..."
- "According to the intake form..."
- "The documents do not specify [X], but..."
- "Subject to verification..."

**Bad (Unhedged):**
- "The contract clearly states..."
- "The defendant admitted..."
- "On March 15, 2024..." (when date not in timeline)
