# Letter Generation

Consolidated reference for the letter generation subsystem. This document merges
sixteen previously separate docs covering findings emails, demand letters,
formatting, citation tracking, quality linting, and prompt engineering.

---

## Context

The system generates professional legal letters driven by AI (OpenAI GPT models)
and formatted as HTML for professional presentation and printing. Two primary
letter types exist today, with a third (recommendation letters) in active
development.

Letters flow through a multi-stage pipeline: AI content generation, two-pass
formatting, citation validation, and deterministic quality linting before they
are persisted and displayed to the attorney.

---

## 1. Letter Types

### Findings Email

A comprehensive case-analysis letter sent to the supervising attorney. Typical
sections include:

- Case overview and procedural history
- Document-by-document analysis with references to uploaded files
- Legal issues identified (construction defect, breach of warranty, etc.)
- Applicable statute citations (Florida Ch. 558, New Mexico statutes, etc.)
- Recommendations and next steps

Generated by `JsonProcessingService.generate_findings_letter_adaptive()` in
`src/legal_portal/services/shared/json_processing_service.py`.

Frontend display component:
`frontend/src/lib/components/FindingsEmailSection.svelte`

### Demand Letter

A formal demand letter suitable for service on opposing parties. Includes:

- Formal demand with legal basis
- Factual recitation and damages summary
- Timeline for response and consequences of non-compliance
- Statute-backed legal authority

Generated by `DemandLetterService.generate_demand_letter()` in
`src/legal_portal/services/letters/demand_letter_service.py`.

Frontend display component:
`frontend/src/lib/components/DemandLetterSection.svelte`

### Recommendation Letter

An emerging letter type for strategic recommendations. Service implementation
lives in `src/legal_portal/services/letters/recommendation_letter_service.py`.

## 2. Letter Format Standard

All letters share a consistent HTML structure wrapped in a
`<div class="legal-letter">` container.

### Structural Sections

| CSS class        | Purpose                                       |
|------------------|-----------------------------------------------|
| `.letter-header` | Law firm letterhead, date, recipient info     |
| `.letter-body`   | Salutation, introduction, legal analysis body |
| `.letter-footer` | Conclusion, signature block, disclaimers      |

### Standard Section Order

1. Header -- firm letterhead, date, recipient address
2. Salutation -- e.g., "Dear Attorney Smith:"
3. Introduction / purpose paragraph
4. Body sections with legal analysis (varies by letter type)
5. Citation references (footnotes or inline)
6. Conclusion with recommended next steps
7. Signature block

### Typography and Print

- Justified text alignment
- Professional serif font stack
- Proper margins for US Letter paper
- Print-friendly `@media print` stylesheet
- No background colors or decorative elements in print output

## 3. Two-Pass Formatting System

Letter content goes through two distinct processing passes before final output.

### Pass 1 -- AI Content Generation

The AI model (currently `gpt-5.4` for letter generation) produces raw content
containing the legal analysis, organized by topic. At this stage the output may
contain:

- Markdown artifacts (headers, bold syntax, bullet markers)
- Code fences (`\`\`\`html`, `\`\`\`markdown`)
- Inconsistent whitespace

Relevant code paths:

- `JsonProcessingService.generate_findings_letter_from_json()` -- structured
  JSON-to-letter pipeline
- `JsonProcessingService.generate_findings_letter_adaptive()` -- adaptive
  generation with fallback strategies
- `DemandLetterService.generate_demand_letter_with_markdown()` -- markdown-first
  demand letter path

### Pass 2 -- Formatting and Cleanup

The formatting pass applies the HTML structure, strips unwanted artifacts, and
validates citations. Key operations:

1. **Code fence removal** -- regex strips `\`\`\`html`, `\`\`\`markdown`, and
   bare `\`\`\`` markers
2. **Markdown-to-HTML conversion** -- remaining markdown syntax converted to
   semantic HTML
3. **Whitespace normalization** -- collapse excessive blank lines, normalize
   indentation
4. **Citation linking** -- inline citation markers linked to source documents
5. **HTML wrapper injection** -- content wrapped in `.legal-letter` structure
   with header/body/footer sections

Implementation files:

- `src/legal_portal/services/shared/document_formatter.py` --
  `DocumentFormatterService` with `format_findings_letter()`,
  `format_demand_letter()`, `format_recommendation_letter()`
- `src/legal_portal/services/letters/content_formatting_service.py` --
  content-level formatting utilities
- `src/legal_portal/utils/markdown_utils.py` -- `clean_markdown_response()`
  standalone utility
- `src/legal_portal/services/shared/json_processing_service.py` --
  `_clean_markdown_response()` method for inline cleanup

## 4. Citation System

### Source Document Tracking

Every uploaded document is tracked through the analysis pipeline with its
original filename preserved. When the AI references a document in the letter, the
citation service maps the reference back to the source file.

Implementation:
`src/legal_portal/services/shared/citation_tracking_service.py` --
`generate_findings_letter_with_citations()`

### Statute Citation Validation

The system validates AI-generated statute citations against curated legal
corpora:

| Jurisdiction | Corpus size                   |
|--------------|-------------------------------|
| Florida      | 51 statutes                   |
| New Mexico   | 42 statutes + 8 court rules   |

Corpus files live in the project root under `florida_legal_corpus/` and
`new_mexico_legal_corpus/`.

Validation logic is in `src/legal_portal/services/analysis/corpus_coverage_service.py`.

### Anti-Hallucination Safeguards

- Citations are validated against the set of actually-uploaded documents; any
  reference to a document not in the case file is flagged.
- Statute numbers are checked against the legal corpus; unrecognized citations
  are surfaced as warnings rather than silently included.

## 5. Quality Checks

### Deterministic Lint

The `LetterQualityLintService` in
`src/legal_portal/services/letters/letter_quality_lint_service.py` runs
rule-based checks on generated letters. It operates in two modes:

- **Standard mode** -- baseline checks applicable to all letter types
- **Strict quality mode** -- tighter constraints for findings emails (word count
  bounds, section completeness)

Each violation carries a severity, and a composite lint score determines
pass/fail.

### Format Validation

`src/legal_portal/utils/letter_formatter.py` provides:

- `LetterFormatter.validate_format()` -- checks for structured professional
  formatting standards
- `format_letter()` -- validates and optionally auto-fixes formatting issues

Checks include:

- No raw markdown syntax in HTML output
- Proper heading hierarchy
- Required sections present (salutation, conclusion, signature)

### Letter Review

`src/legal_portal/services/letters/letter_review_service.py` provides
higher-level review workflows (e.g., attorney approval gates).

### Letter Validation

`src/legal_portal/services/letters/letter_validation_service.py` provides
schema-level validation of letter payloads before persistence.

## 6. AI Prompt Engineering

### Prompt Construction

Prompts are assembled dynamically by `src/legal_portal/utils/prompt_builder.py`.
Key context injected into each prompt:

- Legal issue type and jurisdiction
- Document summaries produced during the analysis phase
- Client and case metadata
- Applicable statute excerpts from the legal corpus

### Letter Strategy

`src/legal_portal/services/letters/letter_strategy_service.py` selects
generation parameters (tone, structure, emphasis) based on case characteristics.

### Model Selection

| Task                        | Default model   |
|-----------------------------|-----------------|
| Letter generation           | `gpt-5.4`      |
| Gap analysis (single-pass)  | `gpt-5.2`      |
| Gap analysis map phase      | `gpt-5-mini`   |
| Gap analysis reduce phase   | `gpt-5.4`      |
| Document extraction (PDF)   | `gpt-5.2`      |
| Group summarization (basic) | `gpt-5-mini`   |

Model preferences are configurable through the AI client's
`get_preferred_model()` mechanism; the values above are defaults defined in
`src/legal_portal/core/data_models.py`.

## 8. Troubleshooting

### Code fences appearing in letter output

The two-pass system should strip all code fences. If they leak through:

1. Check `_clean_markdown_response()` in `json_processing_service.py` -- the
   regex must match the specific fence variant (e.g., ` ```html `, ` ```markdown `,
   bare ` ``` `).
2. Check `clean_markdown_response()` in `utils/markdown_utils.py` for the
   standalone path.
3. Verify the demand letter path calls `_clean_markdown_response()` in
   `demand_letter_service.py`.

### Missing or broken citations

1. Confirm document filenames are preserved through the analysis pipeline (check
   `citation_tracking_service.py`).
2. Verify the case's uploaded documents list matches what the AI was given as
   context.
3. Check for statute citation warnings in logs -- unrecognized statutes are
   logged but not silently dropped.

### Format validation failures

1. Run `format_letter(text)` from `letter_formatter.py` to get a diagnostic
   report listing specific violations.
2. Common causes: heading level skips, missing signature block, leftover markdown
   bold (`**text**`) in HTML output.

### Lint score below threshold

1. Call `LetterQualityLintService.lint_letter()` directly to see individual
   violation severities and the computed score.
2. In strict quality mode (findings emails), check word-count bounds -- letters
   that are too short or too long will fail.

### Letter generation falls back to secondary path

The `fallback_generation_service.py` activates when the primary generation path
raises an exception or times out. Check upstream logs for the root cause (model
API errors, context window exceeded, malformed input JSON).
